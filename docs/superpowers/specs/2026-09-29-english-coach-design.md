# English Coach — local interactive app (Part 1: core + lessons)

Date: 2026-09-29
Status: approved in brainstorming, pending spec review

## Goal

Replace the `it-english-coach` skill loop (generate HTML → answer → copy → paste into Claude Code) with a
local website: lessons generated by a button, instant feedback, lesson history, a mistakes view, and all
learner memory in one place. Must work for teammates from a zip.

## Scope and phases

| Part | Content | This spec |
|---|---|---|
| 1 | Server, storage, Obsidian import, dashboard, lesson player, history, mistakes, settings | **yes** |
| 2 | Vocabulary + chunks with spaced repetition | no |
| 3 | Text dialogue (role-play: stand-up, Slack), review at the end. No voice | no |
| 4 | In-app onboarding + placement test, zip packaging for teammates | no |

## Constraints

- Zero dependencies to install: Python 3 stdlib server, plain HTML/CSS/JS ES modules, no build step.
- AI = the locally installed Claude Code (`claude -p`), user's own login. No API keys.
- Explanations in Ukrainian, examples in English (configurable later).
- Learner data lives only in `data/`; the zip for teammates excludes it.

## Architecture

```
english-coach/
├── start.sh              # checks python3 + claude, runs server.py, opens browser
├── server.py             # http.server: serves web/, routes /api/*
├── coach/
│   ├── storage.py        # atomic JSON read/write for data/
│   ├── claude.py         # single entry point for `claude -p`
│   ├── context.py        # builds the compact memory slice for prompts
│   ├── checker.py        # local answer matching for closed items
│   ├── importer.py       # one-time Obsidian vault → data/ (via Claude)
│   ├── schemas/          # JSON Schemas: lesson, check, review, import
│   └── prompts/          # generate_lesson.md, check_answer.md, review.md, import.md
├── web/
│   ├── index.html, app.js    # hash router
│   ├── api.js                # fetch wrapper
│   ├── views/                # home.js, lesson.js, history.js, mistakes.js, settings.js
│   └── soft.css              # Soft UI, light + dark variable sets
├── tests/                # unittest
└── data/                 # gitignored, per learner
```

### Claude invocation

```
claude -p --output-format json --json-schema <schema> --system-prompt-file <prompt>
       --tools "" --no-session-persistence --model <model> [--setting-sources ""]
```

- Prompt input goes via stdin; the result is parsed from the `json` envelope.
- Must not inherit the user's global `~/.claude/CLAUDE.md` (its "English only" rule breaks Ukrainian
  explanations). **First implementation step:** verify isolation with a real call; if `--setting-sources`
  does not exclude CLAUDE.md, run with a neutral `cwd` and `--system-prompt` override and re-verify.
- Timeout 120 s. Invalid output → one retry, then a readable error.
- Model per task from settings: `generate` (default opus), `check` + `review` (default sonnet).

### Pedagogy

The rules from the skill (focus priority, explain-it-back, recognition → guided → free production,
3–5 corrections per task, never reuse a failed analogy, promotion/demotion rules) move into
`coach/prompts/*.md`. The app becomes self-contained; the skill is not required.

## Data model

`data/profile.json`
```json
{ "name": "", "role": "", "stack": [], "goals": "", "levels": { "grammar": "A1+", "...": "" },
  "settings": { "theme": "auto", "defaultMinutes": 15, "models": { "generate": "opus", "check": "sonnet" } } }
```

`data/skills.json` — replaces Weak Points + Mistakes + Review Queue
```json
[{ "id": "articles", "kind": "grammar|mistake|vocab", "title": "", "status": "weak|improving|stable|mastered",
   "understanding": "none|partial|solid", "count": 12, "examples": [{ "wrong": "", "right": "", "lesson": "" }],
   "due": "2026-09-30", "analogiesTried": [], "notes": "" }]
```

`data/lessons/<id>.json` (`id` = `YYYY-MM-DD-NN`)
```json
{ "id": "", "createdAt": "", "minutes": 15, "topic": "", "rationale": "", "focus": ["skill ids"],
  "status": "in_progress|done",
  "items": [{ "id": "q1", "type": "choice|gap|fix|write|explain|confidence", "section": "",
              "prompt": "", "options": [], "accept": [], "why": "", "skill": "" }],
  "responses": { "q1": { "text": "", "result": "correct|mismatch|wrong|ai", "feedback": "" } },
  "review": { "summary": "", "improved": [], "corrections": [], "nextFocus": "" } }
```

Item count scales with duration: 10 min ≈ 8, 15 ≈ 12, 20 ≈ 16, 30 ≈ 24. Every lesson keeps ≥ 2
free-writing items, one `explain`, one `confidence`.

## Flows

**Generate:** Home → pick minutes → `POST /api/lessons {minutes, focusSkill?}` → `context.py` builds the
slice (profile, top skills by priority, overdue items, last 3 `nextFocus`) → `generate_lesson.md` →
lesson JSON saved → player opens. `focusSkill` comes from "Practise this" on the Mistakes screen.

**Answer:** closed items (`choice`, `gap`, `fix`) are checked in the browser against `accept[]`
(case, whitespace, punctuation and contraction normalised). A match shows ✓ + `why`. For `gap`/`fix`, a
non-match shows "doesn't match the expected answer" plus a **"Check with AI"** button, never a hard ✗.
`write`/`explain` go to `POST /api/check`. Every response is saved to the server immediately, so a
lesson can be resumed.

**Finish:** `POST /api/lessons/<id>/finish` → `review.md` → review JSON + a skills patch (counts,
statuses, due dates, examples, analogies) → applied to `skills.json` → review screen.

**Import:** `POST /api/import {vaultPath}` runs once when `data/` is empty and a vault is found; Claude
maps the md files to `profile.json` + `skills.json` + past lesson summaries.

## Screens

| Screen | Content |
|---|---|
| Home | Next-lesson card (topic, why, 10/15/20/30, Generate), progress ring, bars per area, overdue count |
| Lesson | One item per card, progress bar, instant feedback, hint, finish → review |
| History | Lesson list (date, topic, score, minutes) → read-only replay with answers and corrections |
| Mistakes | Skill cards by count: status, trend, verbatim examples, "Practise this" |
| Settings | Theme ☀/☾/Auto, model per task, default duration |

## Visual design

Soft UI (neumorphism) after the user's reference, light + dark:

- Light `--bg #E6ECF2`, ink `#2E3A4B`, shadows `#FFFFFF` / `#C3CEDA`.
- Dark `--bg #262A33`, ink `#DDE2EC`, shadows `#313643` / `#1A1D24`.
- Accent gradient `#7F8CF5 → #B07CF0` on the primary button and progress only; ok `#4FA39A`, error `#D0708C`.
- Contrast guard: text stays high-contrast; inputs use a deeper inset so they are clearly writable.
- Theme: `auto` follows `prefers-color-scheme`, manual choice stored in `localStorage`.

## Error handling

- `claude` missing or not logged in → banner on Home with the exact command to run; AI buttons disabled
  with a tooltip reason.
- Generation or check fails → message with a retry button; the lesson state is untouched.
- Writes are atomic (temp file + `os.replace`).

## Testing

`python3 -m unittest` with no third-party packages: storage, checker normalisation, context builder,
skills patch application, importer mapping, API routes with `claude.py` mocked. The UI is checked
manually in the browser for each screen, in both themes.

## Out of scope for Part 1

Vocabulary SRS, dialogue, voice, onboarding/placement test, zip packaging, multi-user on one machine.
